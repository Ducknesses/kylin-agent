### 4.1 test_action_service.py / test_actions_api.py（18个失败）

|---------|---------|------|
| test_harness_called_once | ValueError | ActionService 内部状态校验变更 |
| test_stored_high_action_blocked | ValueError | 高风险动作的存储逻辑需调整 |
| test_high_no_harness_no_claim | ValueError | 同上，高风险动作校验逻辑 |
| test_safety_blocked_action_blocked | ValueError | 安全拦截后的动作状态管理 |
| test_blocked_audit_has_option_id | ValueError | 审计记录中option_id字段缺失 |
| test_medium_confirm_id_and_created_audit | ValueError | 中危确认流程审计记录 |
| test_medium_repeat_no_duplicate_audit | ValueError | 重复确认审计去重 |
| test_medium_audit_has_confirm_id | ValueError | 审计记录中confirm_id字段 |
| test_medium_concurrent_same_confirm_id | ValueError | 并发确认逻辑 |
| test_wrong_session_returns_not_found | ValueError | 会话校验 |
| test_expired_confirm_returns_expired | ValueError / AssertionError | 过期确认状态码（预期410，实际不同） |
| test_expired_reject_returns_expired | AssertionError | 同上 |
| test_approve_blocked_audit_has_confirm_id | ValueError | 批准的审计记录字段 |
| test_no_confirmation_store_returns_error | ValueError | 无确认存储时的错误处理 |
| test_medium_returns_200_confirm_required | ValueError | API层确认返回 |
| test_high_returns_403 | ValueError | API层高风险拒绝 |
| test_expired_approve_returns_410 | 断言失败 | API层过期确认 |
| test_expired_reject_returns_410 | 断言失败 | API层过期拒绝 |

**根因**: 测试用例间 option_id 硬编码重复，导致 Redis 状态污染。`FixOptionStore.save_options()` 在 `fix_option_store.py:195` 检测同 session + option_id 是否存在非终态记录，若存在则抛 `ValueError`。18个失败用例使用了相同的硬编码 option_id（如 `fix_22222222`、`fix_faf1ce19`），前一个测试写入的 option 未被清理，后续测试重复使用时触发异常。

**修复方案**: 将所有硬编码 option_id 改为动态生成唯一UUID（详见《测试问题修复计划》）。

### 4.2 test_orchestrator_llm_integration.py / test_llm_safety_boundary.py（9个失败）
