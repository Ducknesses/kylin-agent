# 麒麟智能运维 Agent (kylin-agent) — 部署文档

> **版本**：0.1.0  
> **目标平台**：麒麟 V11 (LoongArch) 目标机 + Linux (x86_64 / ARM / LoongArch) 控制节点  
> **文档更新日期**：2026-07-20（控制节点 LoongArch 兼容性验证通过）

---

## 一、部署架构概览

```
                        ┌──────────────────────┐
                        │    用户浏览器          │
                        │  https://控制节点IP    │
                        └──────────┬───────────┘
                                   │ HTTPS / WSS
┌──────────────────────────────────┼──────────────────────────────────┐
│                       控制节点 (x86_64 / ARM / LoongArch)            │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  Nginx :443                                                   │  │
│  │  ├─ 静态文件服务 (/opt/kylin-agent/frontend/dist/)             │  │
│  │  ├─ /api/*   → proxy_pass http://127.0.0.1:8000               │  │
│  │  ├─ /ws/*    → proxy_pass http://127.0.0.1:8000 (WSS升级)     │  │
│  │  └─ /health  → proxy_pass http://127.0.0.1:8000               │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  Backend :8000 (FastAPI + Uvicorn)                            │  │
│  │  systemd 服务: kylin-agent.service                             │  │
│  │  安装路径: /opt/kylin-agent/backend/                           │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  ┌────────────────┐  ┌──────────────────┐                          │
│  │  Redis :6379    │  │  SQLite          │                          │
│  │  (会话/状态缓存) │  │  (审计日志+哈希链) │                          │
│  └────────────────┘  └──────────────────┘                          │
└─────────────────────────────────────────────────────────────────────┘
                                   │ HTTPS + Bearer Token
┌──────────────────────────────────┼──────────────────────────────────┐
│                     麒麟 V11 目标机 (LoongArch)                      │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  MCP Server :8001                                             │  │
│  │  systemd 服务: mcp-server.service                             │  │
│  │  安装路径: /opt/mcp-server/                                    │  │
│  │  执行用户: agent-read (只读) / agent-op (sudo白名单)            │  │
│  └──────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
```

**三个组件可独立部署**，无强耦合依赖：

| 组件 | 部署位置 | 安装脚本 | 使用端口 |
|------|---------|---------|---------|
| Backend | 控制节点 | `deploy/backend/install.sh` | 8000 (内部) |
| Frontend + Nginx | 控制节点 | `deploy/frontend/install.sh` | 443 (对外) |
| MCP Server | 麒麟目标机 | `deploy/mcp-server/install.sh` | 8001 (内部) |

## 二、环境要求

### 2.1 控制节点

| 项目 | 最低要求 |
|------|---------|
| 操作系统 | Linux (x86_64 / ARM / LoongArch)，推荐 Ubuntu 20.04+ / RHEL 8+ / 麒麟 V10 |
| Python | ≥ 3.10（需含 venv 模块） |
| Node.js | ≥ 18（仅构建前端时需要） |
| npm | ≥ 9（仅构建前端时需要） |
| Redis | 可选（内置 fakeredis fallback），生产环境建议 `redis-server` |
| 磁盘空间 | ≥ 500 MB（含前端构建产物和 Python 虚拟环境） |
| 网络 | 能访问麒麟目标机的 MCP Server 端口（默认 8001）；能访问 DeepSeek API（若启用 LLM） |

### 2.2 麒麟 V11 目标机

| 项目 | 最低要求 |
|------|---------|
| 操作系统 | 麒麟 V11（LoongArch） |
| Python | ≥ 3.6（需含 pip 和 venv 模块） |
| 关键包 | `psutil`, `python-dotenv` |
| 系统用户 | `agent-read`（只读）和 `agent-op`（操作）由安装脚本自动创建 |
| 磁盘空间 | ≥ 200 MB |

## 四、开发环境部署

适用于本地开发和调试，三端均在同一台机器上运行。

### 4.1 启动后端

```bash
cd backend

# 创建虚拟环境
python3 -m venv .venv
source .venv/bin/activate

# 安装依赖
pip install -r requirements.txt

# 配置环境变量（从模板复制）
cp .env.example .env
# 编辑 .env，至少填写 DEEPSEEK_API_KEY（如果启用 LLM）

# 启动（默认 127.0.0.1:8000）
python run.py
```

验证：

```bash
curl http://localhost:8000/health
# → {"status":"ok","version":"0.1.0"}
```

### 4.2 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://localhost:5173`，Vite 自动代理 `/api` 和 `/ws` 到后端 `127.0.0.1:8000`。

### 4.3 启动 MCP Server（可选）

```bash
cd mcp-server
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python server.py
# 监听 127.0.0.1:8001
```

## 五、生产环境部署

### 5.1 Backend 部署（控制节点）

#### 步骤一：执行安装脚本

```bash
# 需要 root 权限
sudo ./deploy/backend/install.sh
```

**安装脚本自动完成：**
1. 检查 Python ≥ 3.10
2. 创建系统用户 `agent-read`（自动检测 nologin shell 路径）
3. 复制项目文件到 `/opt/kylin-agent/backend/`（排除 tests、logs、__pycache__、venv）
4. 若 `/opt/kylin-agent/backend/.env` 不存在，从 `.env.example` 创建
5. 创建 Python 虚拟环境 `venv` 并安装所有依赖
6. 创建 `data/` 和 `logs/` 目录（权限 775）
7. 安装 `kylin-agent.service` systemd 服务
8. 设置目录所有者为 `agent-read:agent-read`
9. 执行 `systemctl daemon-reload` 和 `systemctl enable kylin-agent`

#### 步骤二：配置环境变量

```bash
sudo vim /opt/kylin-agent/backend/.env
```

**必须配置的关键项：**

| 变量 | 说明 | 示例值 |
|------|------|--------|
| `DEEPSEEK_API_KEY` | DeepSeek API 密钥（启用 LLM 时必填） | `sk-xxxxxxxxxxxxxxxx` |
| `LLM_ENABLED` | LLM 开关 | `true` 或 `false`（规则版 fallback） |
| `MCP_MODE` | MCP 模式 | `real`（生产）或 `mock`（开发） |
| `MCP_SERVER_URL` | MCP Server 地址 | `http://192.168.56.101:8001` |
| `MCP_AUTH_TOKEN` | MCP 认证 Token（须与 MCP Server 一致） | `<your-token>` |
| `API_TOKEN` | 单 Token 认证 | `<your-api-token>` |
| `API_TOKENS` | 多 Token 分级认证（与 API_TOKEN 二选一） | `read:rk_xxx,op:op_yyy,admin:adm_zzz` |
| `APP_HOST` | 监听地址 | `127.0.0.1`（仅本地，通过 Nginx 代理） |
| `APP_PORT` | 监听端口 | `8000` |
| `REDIS_URL` | Redis 连接 | `redis://localhost:6379/0`（留空则用 fakeredis） |

**完整配置项参考 `backend/.env.example`。**

#### 步骤三：启动与验证

```bash
# 启动服务
sudo systemctl start kylin-agent

# 设置开机自启
sudo systemctl enable kylin-agent

# 查看运行状态
sudo systemctl status kylin-agent

# 查看实时日志
sudo journalctl -u kylin-agent -f

# 健康检查
curl http://127.0.0.1:8000/health
# → {"status":"ok","version":"0.1.0"}
```

#### 步骤四：运行诊断工具

```bash
cd /opt/kylin-agent/backend
python3 diagnose.py --non-interactive
```

诊断工具会检查：依赖 → 监听地址配置 → LLM/MCP配置 → 启动状态 → 网络连通性。

### 5.2 Frontend + Nginx 部署（控制节点）

#### 前置条件

- Backend 已部署并运行在 `127.0.0.1:8000`
- Node.js ≥ 18 已安装

#### 步骤一：构建前端产物

```bash
cd frontend
npm install
npm run build
cd ..
```

构建产物位于 `frontend/dist/`。

#### 步骤二：执行安装脚本

```bash
sudo ./deploy/frontend/install.sh
```

**安装脚本自动完成：**
1. 检查 `frontend/dist/` 存在，不存在则自动 `npm install && npm run build`
2. 复制静态文件到 `/opt/kylin-agent/frontend/dist/`
3. 自动生成自签名 SSL 证书（RSA 2048 位，3650 天，CN=本机 hostname）
   - 证书路径：`/etc/nginx/certs/kylin-agent.crt`
   - 私钥路径：`/etc/nginx/certs/kylin-agent.key`
4. 自动检测包管理器（apt / dnf / yum），安装 Nginx
5. 部署 Nginx 配置文件：
   - Debian/Ubuntu：`/etc/nginx/sites-available/kylin-agent` → `sites-enabled/`
   - RHEL/麒麟：`/etc/nginx/conf.d/kylin-agent.conf`
6. 设置目录所有者 `agent-read:agent-read`，权限 755
7. 处理 SELinux 策略（如 enforcing，设置 httpd_sys_content_t 上下文和 httpd_can_network_connect）
8. 将 Nginx 用户加入 agent-read 组

#### Nginx 配置说明

```
upstream kylin_backend {
    server 127.0.0.1:8000;     # Backend 上游
    keepalive 32;
}

# HTTP (80) → HTTPS (443) 强制跳转
server { listen 80; return 301 https://$host$request_uri; }

# HTTPS 主入口
server {
    listen 443 ssl http2;
    
    # SSL 配置
    ssl_certificate     /etc/nginx/certs/kylin-agent.crt;
    ssl_certificate_key /etc/nginx/certs/kylin-agent.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    
    # 安全响应头
    add_header Strict-Transport-Security "max-age=63072000" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    
    # 前端静态文件
    root /opt/kylin-agent/frontend/dist;
    location / { try_files $uri $uri/ /index.html; }
    
    # SSE 监控流（关闭代理缓冲）
    location /api/monitor/stream {
        proxy_pass http://kylin_backend;
        proxy_buffering off;
        proxy_read_timeout 86400s;
    }
    
    # REST API 反向代理
    location /api/ {
        proxy_pass http://kylin_backend;
        proxy_read_timeout 120s;
    }
    
    # WebSocket / WSS 升级
    location /ws/ {
        proxy_pass http://kylin_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400s;
    }
    
    # 健康检查
    location /health {
        proxy_pass http://kylin_backend;
    }
}
```

#### 步骤三：验证前端

```bash
# 检查 Nginx 状态
sudo systemctl status nginx

# 验证 Nginx 配置
sudo nginx -t

# 浏览器访问
# https://<控制节点IP>
```

> **生产环境 SSL 证书替换：** 安装脚本生成的是自签名证书，浏览器会提示安全警告。如需正式证书：
> ```bash
> # 使用 Let's Encrypt (certbot)
> sudo apt install certbot python3-certbot-nginx
> sudo certbot --nginx -d your-domain.com
> ```
> 或手动替换 `/etc/nginx/certs/kylin-agent.{crt,key}` 后重启 Nginx。

### 5.3 MCP Server 部署（麒麟 V11 目标机）

#### 步骤一：执行安装脚本

```bash
# 将源码中的 mcp-server/ 目录和 deploy/mcp-server/ 目录复制到麒麟目标机

# 在目标机上执行
sudo ./deploy/mcp-server/install.sh
```

**安装脚本自动完成：**
1. **LoongArch 架构兼容性检查**（脚本 `loongarch-check.sh`）
   - 验证 CPU 架构为 loongarch64
   - 检查 Python ≥ 3.6，含 pip 和 venv 模块
2. 创建专用系统用户：
   - `agent-read`：只读权限，用于 sys_info、log_reader、net_monitor 等工具
   - `agent-op`：操作权限，用于 service_mgr、cmd_exec 等工具
3. 复制项目文件到 `/opt/mcp-server/`，创建虚拟环境并安装依赖（psutil, python-dotenv）
4. 配置 sudoers 白名单：`/etc/sudoers.d/agent-op`
   - `agent-read` 可执行 `systemctl status` 等只读命令
   - `agent-op` 可执行 `systemctl start/stop/restart/reload` 等操作命令
5. 创建 `whitelist_rules.json` 命令白名单配置文件
6. 安装 `mcp-server.service` systemd 服务
7. 执行 `systemctl daemon-reload` 和 `systemctl enable mcp-server`

#### 步骤二：运行配置向导

```bash
cd /opt/mcp-server && sudo bash wizard.sh
```

**向导会交互式引导设置：**

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 监听端口 | 8001 | MCP Server 监听端口 |
| 监听地址 | 0.0.0.0 | 监听所有网络接口 |
| 认证 Token | （随机生成） | 与控制节点 Backend 的 MCP_AUTH_TOKEN 保持一致 |
| 防火墙规则 | 自动放行 | 自动添加监听端口到防火墙 |

> **重要：** 请务必使用 `wizard.sh` 向导修改配置，不要直接用文本编辑器修改 `/opt/mcp-server/.env` 文件，否则可能因编码或换行符格式异常导致配置无法正确读取。

#### 步骤三：启动与验证

```bash
# 启动服务
sudo systemctl start mcp-server

# 设置开机自启
sudo systemctl enable mcp-server

# 查看运行状态
sudo systemctl status mcp-server

# 查看实时日志
sudo journalctl -u mcp-server -f

# 在目标机上健康检查
curl http://127.0.0.1:8001/health
```

#### 步骤四：验证控制节点到目标机的连通性

```bash
# 在控制节点上执行
curl http://<麒麟目标机IP>:8001/health
# 应返回健康状态
```

### 5.4 配置 Backend 对接 MCP Server

在 Backend 的 `.env` 中配置 MCP 连接参数：

```bash
sudo vim /opt/kylin-agent/backend/.env
```

确保以下配置正确：

```ini
MCP_MODE=real                                         # 必须为 real
MCP_SERVER_URL=http://<麒麟目标机IP>:8001              # MCP Server 地址
MCP_AUTH_TOKEN=<与 wizard.sh 中设置的 Token 一致>       # 认证 Token
```

配置修改后重启 Backend：

```bash
sudo systemctl restart kylin-agent
sudo journalctl -u kylin-agent -f  # 确认无配置错误
```

## 七、服务管理

### 7.1 systemd 服务命令

```bash
# ── Backend (kylin-agent.service) ──
sudo systemctl start kylin-agent       # 启动
sudo systemctl stop kylin-agent        # 停止
sudo systemctl restart kylin-agent     # 重启
sudo systemctl status kylin-agent      # 状态
sudo systemctl enable kylin-agent      # 开机自启
sudo systemctl disable kylin-agent     # 取消自启
sudo journalctl -u kylin-agent -f      # 实时日志
sudo journalctl -u kylin-agent -n 100  # 最近 100 行日志

# ── MCP Server (mcp-server.service) ──
sudo systemctl start mcp-server
sudo systemctl stop mcp-server
sudo systemctl restart mcp-server
sudo systemctl status mcp-server
sudo systemctl enable mcp-server
sudo journalctl -u mcp-server -f

# ── Nginx ──
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl reload nginx            # 重载配置（不中断服务）
sudo systemctl restart nginx
sudo systemctl status nginx
```

### 7.2 防火墙管理

```bash
# ── firewalld（RHEL/麒麟）──
sudo firewall-cmd --zone=public --add-service=https --permanent  # 放行 HTTPS
sudo firewall-cmd --zone=public --add-port=8001/tcp --permanent  # 放行 MCP Server
sudo firewall-cmd --reload
sudo firewall-cmd --list-all

# ── ufw（Ubuntu/Debian）──
sudo ufw allow 443/tcp
sudo ufw allow 8001/tcp
sudo ufw reload
sudo ufw status

# ── iptables ──
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 8001 -j ACCEPT
```

|------|--------|------|
| `MCP_HOST` | `0.0.0.0` | 监听地址 |
| `MCP_PORT` | `8001` | 监听端口 |
| `AUTH_TOKEN` | — | 认证 Token（须与 Backend 的 MCP_AUTH_TOKEN 一致） |
| `CGROUP_ENABLED` | `true` | 是否启用 cgroups 资源隔离 |
| `CGROUP_CPU_LIMIT` | `50` | CPU 使用率上限（%） |
| `CGROUP_MEMORY_LIMIT` | `256` | 内存上限（MB） |
| `CGROUP_MAX_PIDS` | `64` | 最大进程数（防 fork bomb） |

> **注意：** MCP Server 的配置请使用 `wizard.sh` 向导修改，不要直接编辑 `.env` 文件。

### 8.3 cgroups 资源隔离

MCP Server 的 `sandbox.py` 支持 cgroups v2 资源隔离，为每个命令执行创建隔离沙箱：

| 限制项 | 配置变量 | 默认值 | 说明 |
|--------|---------|--------|------|
| CPU 配额 | `CGROUP_CPU_LIMIT` | 50 | CPU 使用率百分比上限 |
| 内存上限 | `CGROUP_MEMORY_LIMIT` | 256 | 最大内存使用量（MB） |
| PID 数量 | `CGROUP_MAX_PIDS` | 64 | 最大进程数，防止 fork bomb |

如需关闭 cgroups 隔离：在 `/opt/mcp-server/.env` 中设置 `CGROUP_ENABLED=false`（使用 `wizard.sh` 修改）。

## 九、常见问题排查

### 9.1 MCP Server 不可访问

**检查流程：**

1. **检查 MCP Server 服务状态**
   ```bash
   sudo systemctl status mcp-server
   ```

2. **检查依赖安装**
   ```bash
   sudo /opt/mcp-server/venv/bin/pip install --upgrade pip
   sudo /opt/mcp-server/venv/bin/pip install -r /opt/mcp-server/requirements.txt
   sudo /opt/mcp-server/venv/bin/python -c "import psutil; import dotenv; print('OK')"
   ```

3. **检查端口监听**
   ```bash
   sudo ss -tlnp | grep 8001
   ```

4. **使用向导重新配置**
   ```bash
   cd /opt/mcp-server && sudo bash wizard.sh
   ```

5. **检查防火墙**
   ```bash
   # firewalld
   sudo firewall-cmd --zone=public --add-port=8001/tcp --permanent && sudo firewall-cmd --reload
   
   # ufw
   sudo ufw allow 8001/tcp && sudo ufw reload
   ```

6. **检查 Token 一致性**
   ```bash
   # 在目标机上
   grep 'AUTH_TOKEN' /opt/mcp-server/.env
   # 在控制节点上
   grep 'MCP_AUTH_TOKEN' /opt/kylin-agent/backend/.env
   # 两边的 Token 值必须完全一致
   ```

### 9.2 前端无法访问后端

**检查流程：**

1. **检查 Backend 运行状态**
   ```bash
   sudo systemctl status kylin-agent
   curl http://127.0.0.1:8000/health
   ```

2. **检查端口占用**
   ```bash
   sudo ss -tlnp | grep 8000
   # 如果端口被占用，终止占用进程后重启
   sudo fuser -k 8000/tcp
   sudo systemctl restart kylin-agent
   ```

3. **检查 Nginx 配置与状态**
   ```bash
   sudo nginx -t
   sudo systemctl status nginx
   ```

4. **检查 Nginx 代理配置**
   ```bash
   # 确认 proxy_pass 指向 127.0.0.1:8000
   cat /etc/nginx/sites-available/kylin-agent | grep proxy_pass
   # 或
   cat /etc/nginx/conf.d/kylin-agent.conf | grep proxy_pass
   ```

5. **检查系统代理设置**
   ```bash
   env | grep -i proxy
   # 确保 127.0.0.1 和 localhost 在 NO_PROXY 中
   ```

### 9.3 指令不在白名单 / Permission Denied

1. **通过前端管理界面添加**
   - 登录前端（需 ADMIN 权限）
   - 进入「配置管理」→「白名单设置」
   - 添加指令到对应权限级别

2. **通过 API 管理**
   ```bash
   curl -H "Authorization: Bearer <ADMIN_TOKEN>" \
     http://127.0.0.1:8000/api/config/whitelist
   ```

3. **检查目标机 sudoers 配置**
   ```bash
   sudo cat /etc/sudoers.d/agent-op
   # 如文件缺失，重新复制
   sudo cp deploy/mcp-server/agent-op.sudoers /etc/sudoers.d/agent-op
   sudo chmod 440 /etc/sudoers.d/agent-op
   ```

4. **检查 MCP Server 沙箱白名单**
   ```bash
   cat /opt/mcp-server/whitelist_rules.json
   ```

### 9.4 Backend 启动失败

**常见原因与解决：**

| 症状 | 原因 | 解决方案 |
|------|------|---------|
| `ImportError: No module named 'fastapi'` | Python 依赖未安装 | `sudo /opt/kylin-agent/backend/venv/bin/pip install -r /opt/kylin-agent/backend/requirements.txt` |
| `Address already in use` | 端口被占用 | `sudo fuser -k 8000/tcp && sudo systemctl restart kylin-agent` |
| Redis 连接失败 | Redis 未运行 | 安装 fakeredis 自动 fallback，或 `sudo apt install redis-server` |
| 配置文件错误 | .env 格式问题 | 从 `.env.example` 重新创建并编辑 |

## 十一、安全加固建议

1. **SSL 证书**：生产环境务必替换自签名为正式证书（Let's Encrypt 或企业 CA）
2. **Token 安全**：
   - 使用高强度随机 Token（建议 ≥ 32 字符）
   - 控制节点 Backend 与目标机 MCP Server 使用不同 Token
   - 定期轮换 Token
3. **网络隔离**：
   - Backend 仅监听 `127.0.0.1`，通过 Nginx 代理外部请求
   - MCP Server 端口仅对控制节点 IP 开放（防火墙白名单）
4. **最小权限**：
   - MCP Server 执行用户 `agent-read` / `agent-op` 仅授予必需权限
   - sudoers 白名单仅包含必要命令
5. **审计**：定期使用 `/api/audit/verify` 验证审计链完整性
6. **cgroups**：保持资源隔离开启（`CGROUP_ENABLED=true`），防止命令执行消耗过多资源
