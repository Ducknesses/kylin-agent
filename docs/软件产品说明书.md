## 一、产品概述

### 1.1 产品定位

麒麟智能运维 Agent（kylin-agent）是一款面向国产麒麟操作系统的安全智能运维助手。用户通过**自然语言对话**描述运维问题，系统自动完成**意图识别 → 安全审查 → 诊断分析 → 修复规划 → 报告生成**的完整闭环，在保障系统安全的前提下显著降低运维门槛。

本产品为中国软件杯赛题 A2「面向麒麟操作系统的安全智能运维 Agent」的参赛作品。

### 1.2 核心价值

| 维度 | 价值 |
|------|------|
| **易用性** | 自然语言交互，无命令行基础的用户也能完成日常运维操作 |
| **安全性** | 七层纵深防御：输入护栏 → Prompt 注入检测 → 意图识别 → 工具安全裁决 → RBAC 执行 → cgroup 沙箱 → 哈希链审计 |
| **智能化** | 基于大语言模型（DeepSeek）进行根因分析和修复方案推荐，支持多 Agent 协作编排 |
| **架构分离** | 控制节点（推理/编排）与目标机（命令执行）物理分离，敏感操作不直接暴露 |
| **可审计** | 全链路操作记录 SHA256 哈希链防篡改，满足合规审计要求 |

### 1.3 适用场景

- 系统服务异常诊断与恢复（如 nginx、sshd 等服务启动失败）
- 系统资源监控与告警（CPU、内存、磁盘、网络）
- 日志分析与故障排查
- 文件系统状态检查
- 运维知识问答与操作建议
- 系统安全巡检与配置合规检查

## 二、系统架构

### 2.1 部署架构

```
┌─ 用户浏览器 ──────────────────────────────────────────┐
│  前端: Vue 3 + Vite (端口 5173 dev / Nginx :443 prod)  │
└──────────────────────┬────────────────────────────────┘
                       │ HTTPS / WSS
┌─ 控制节点 (x86_64 / ARM / LoongArch) ────────────────┐
│  Nginx :443 → 静态文件 + API 反向代理 + WSS 升级       │
│  Backend :8000 → FastAPI + 多 Agent 编排 + LLM 路由    │
│  Redis :6379 → 会话缓存 + 确认状态存储 + 任务持久化    │
│  SQLite → 审计日志 (哈希链防篡改)                      │
└──────────────────────┬────────────────────────────────┘
                       │ HTTPS + Bearer Token
┌─ 麒麟 V11 目标机 (LoongArch) ────────────────────────┐
│  MCP Server :8001 → 系统信息 / 服务管理 / 日志读取 / … │
│  权限: agent-read (只读) / agent-op (sudo 白名单)      │
└──────────────────────────────────────────────────────┘
```

### 2.2 技术架构

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 后端框架 | FastAPI + Uvicorn | 异步 Web 框架，原生支持 WebSocket 和 SSE |
| 大语言模型 | DeepSeek API | 支持流式/非流式推理，可切换 OpenAI 兼容接口 |
| 实时通信 | WebSocket + SSE | WebSocket 用于对话交互，SSE 用于系统监控推送 |
| 缓存/状态 | Redis | 会话状态、确认状态存储（内置 fakeredis fallback） |
| 审计持久化 | SQLite + aiosqlite | 哈希链防篡改审计日志 |
| MCP 协议 | JSON-RPC 2.0 over HTTP | 标准协议对接目标机 Agent |
| 前端 | Vue 3 + Vite + Pinia | 现代前端框架，组件化开发 |
| 部署 | systemd + venv + Nginx | 原生 systemd 服务管理，无容器依赖 |
| 目标平台 | 麒麟 V11 (LoongArch) | 国产 CPU 架构适配 |

### 2.3 安全模型（七层纵深防御）

```
用户输入
  ↓
第1层: 安全护栏 (safety_guard.py)
  ├─ 长度检查 (MAX_INPUT_LENGTH)
  ├─ 高危正则黑名单 (rm -rf /, mkfs, dd, fork bomb 等)
  ├─ Prompt 注入检测 (控制字符 → Unicode混淆 → 重复字符 → 关键词 → 语义边界)
  └─ 中危关键词 (kill -9, chmod 777 等) → 返回 reject / confirm / allow
  ↓
第2层: 意图识别 (intent_agent.py)
  ↓
第3层: 多 Agent 编排 (orchestrator.py)
  ├─ DiagnoseAgent → 根因分析
  ├─ FixPlannerAgent → 修复方案生成
  └─ ReporterAgent → 报告生成
  ↓
第4层: 工具调用安全裁决 (safety_guard.py + security_rules.py)
  ├─ 工具分发检查 + 高危模式拦截
  ├─ 危险模式拦截 (;, &&, |, `, $() 等 shell 元字符)
  └─ 角色分级: viewer → operator → admin
  ↓
第5层: MCP Server 执行 (麒麟目标机)
  ├─ agent-read: 只读 (sys_info, log_reader, net_monitor)
  └─ agent-op: sudo 白名单 (systemctl status/start/stop/restart/reload)
  ↓
第6层: cgroup 资源隔离 (sandbox.py)
  ├─ CPU 配额限制 (默认 50%)
  ├─ 内存上限 (默认 256MB)
  ├─ PID 数量限制 (防 fork bomb)
  └─ 可配置开关: CGROUP_ENABLED=true
  ↓
第7层: 审计记录 (哈希链防篡改)
  ├─ SQLite audit_chain 表
  └─ SHA256 链式哈希: hash(prev_hash + current_data)
```

## 三、功能模块

| **配置管理** | `ConfigPanel.vue` | 三级白名单（READ / OP / ADMIN）可视化管理 |
| **连接设置** | `ConnectionSettings.vue` | 后端 API 地址、WebSocket 地址配置 |
| **修复选项** | `FixOptionsCard.vue` | 修复方案卡片展示，支持确认执行 |

| **工具调用** | `ToolCallCard.vue` | MCP 工具调用过程与结果展示 |

### 3.2 后端功能（FastAPI 服务）

#### 3.2.1 REST API

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| `GET` | `/health` | 无 | 健康检查 |
| `WS` | `/ws/chat/{session_id}` | Token | WebSocket 聊天（安全检测 → LLM → 审计） |
| `GET` | `/api/sessions` | Token | 列出所有会话 |
| `POST` | `/api/sessions` | Token | 创建新会话 |
| `GET` | `/api/sessions/{id}` | Token | 获取单个会话详情 |
| `DELETE` | `/api/sessions/{id}` | Token | 删除会话 |
| `GET` | `/api/monitor/stream` | Token | SSE 系统监控流（实时推送） |
| `GET` | `/api/audit` | Token | 审计日志查询（分页: `?limit=&offset=`） |
| `GET` | `/api/audit/verify` | Token | 审计链完整性验证 |
| `GET` | `/api/config/whitelist` | Token | 查看三级白名单 |
| `PUT` | `/api/config/whitelist` | ADMIN | 更新白名单 |
| `POST` | `/api/actions` | Token | 提交修复动作 |
| `GET` | `/api/actions/{id}` | Token | 查询修复动作状态 |

#### 3.2.2 多 Agent 协作引擎

| Agent | 核心文件 | 职责 |
|-------|---------|------|
| **IntentAgent** | `intent_agent.py` | 意图识别：判断用户输入属于诊断/修复/监控/问答哪类请求 |
| **DiagnoseAgent** | `diagnose_agent.py` | 诊断分析：多轮工具调用收集信息，给出根因分析 |
| **FixPlannerAgent** | `fix_planner_agent.py` | 修复规划：基于诊断结果生成可执行修复方案，含风险评估 |
| **ReporterAgent** | `reporter_agent.py` | 报告生成：将诊断和修复结果格式化为结构化报告 |
| **Orchestrator** | `orchestrator.py` | 编排协调：按流程串联各 Agent，管理上下文与状态流转 |

#### 3.2.3 MCP 工具集（6 个工具）

| 工具名称 | 权限级别 | 功能 |
|---------|---------|------|
| `sys_info` | READ | 采集系统基本信息：OS 版本、内核、CPU、内存、磁盘使用率 |
| `service_mgr` | OP | systemd 服务管理：status / start / stop / restart / reload |
| `log_reader` | READ | 读取系统日志：syslog / journalctl / dmesg |
| `net_monitor` | READ | 网络状态监控：接口、连接、端口监听、防火墙规则 |
| `cmd_exec` | ADMIN | 安全命令执行（受沙箱白名单限制） |
| `file_guard` | READ | 文件系统信息：目录列表、权限检查、文件校验 |

## 四、认证与权限

### 4.1 Token 认证

支持两种模式：

| 模式 | 配置方式 | 说明 |
|------|---------|------|
| 单 Token | `API_TOKEN=<token>` | 所有请求使用同一 Token，默认为 ADMIN 权限 |
| 多 Token 分级 | `API_TOKENS=read:rk_xxx,op:op_yyy,admin:adm_zzz` | 按 Token 前缀区分权限级别 |

### 4.2 三级 RBAC

| 权限级别 | 能力范围 | 典型用户 |
|---------|---------|---------|
| **READ** | 查看系统信息、日志、监控数据 | 运维观察员 |
| **OP** | READ + systemd 服务管理（启停重启） | 运维操作员 |
| **ADMIN** | OP + 白名单管理、配置修改、命令执行 | 系统管理员 |

## 五、部署方式

### 5.1 环境要求

| 组件 | 部署位置 | 操作系统 | 关键依赖 |
|------|---------|---------|---------|
| Backend | 控制节点 | Linux (x86_64 / ARM / LoongArch) | Python ≥ 3.10, Redis（可选） |
| Frontend | 控制节点 | Linux (x86_64 / ARM / LoongArch) | Node.js ≥ 18, Nginx |
| MCP Server | 麒麟目标机 | 麒麟 V11 (LoongArch) | Python ≥ 3.6, psutil |

### 5.2 一键部署

三个组件均提供一键安装脚本，支持自动依赖安装、用户创建、权限配置、systemd 服务注册。

```bash
# Backend 部署（控制节点）
sudo ./deploy/backend/install.sh

# Frontend + Nginx 部署（控制节点，需先 npm run build）
sudo ./deploy/frontend/install.sh

# MCP Server 部署（麒麟目标机）
sudo ./deploy/mcp-server/install.sh
```

详细部署步骤参见《麒麟智能运维 Agent 部署文档》。

## 六、辅助工具

### 6.1 诊断工具（diagnose.py）

Backend 内置 CLI 诊断工具，支持离线检测和交互式配置修改：

| 选项 | 功能 |
|------|------|
| `python diagnose.py` | 完整交互模式：依赖检测 + 监听地址修改 + LLM/MCP 配置修改 + 启动状态检测 + 网络连通性检测 |
| `python diagnose.py --quick` | 跳过依赖检测，其余同上 |
| `python diagnose.py --non-interactive` | 仅检测不修改，适合 CI/脚本 |

### 6.2 配置向导（wizard.sh）

MCP Server 部署后在目标机上运行：

```bash
cd /opt/mcp-server && sudo bash wizard.sh
```

交互式引导设置：监听端口、监听地址、认证 Token、防火墙规则。

## 八、使用流程示例

### 场景：nginx 服务无法启动

1. **用户输入**：「nginx 服务启动失败了，帮我看看」
2. **安全护栏**：输入通过安全检测，无危险指令
3. **意图识别**：系统判定为「诊断请求」
4. **诊断 Agent**：自动调用 `service_mgr.status("nginx")`、`log_reader.read("nginx")` 等工具，分析失败原因
5. **报告 Agent**：生成诊断报告，指出「端口 80 被占用」
6. **修复规划 Agent**：建议「停止占用进程并重启 nginx」，附带风险评估
7. **用户确认**：前端展示修复方案，用户点击确认
8. **安全裁决**：验证修复指令在白名单内，通过 RBAC 检查
9. **MCP 执行**：在目标机上执行修复操作
10. **审计记录**：全链路操作写入审计链
11. **结果反馈**：「nginx 服务已成功启动」

```

├── backend/                 # Python FastAPI 后端（控制节点）
```
