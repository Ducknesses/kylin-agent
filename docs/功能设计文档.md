## 1. 项目概述

### 1.1 项目定位

麒麟智能运维 Agent 是一个面向麒麟操作系统（Kylin OS）的安全智能运维助手。用户通过自然语言描述运维问题，系统自动完成意图识别、安全审查、诊断规划、工具执行、报告生成和修复方案推荐的完整闭环。

### 1.2 核心设计原则

- **LLM 不做决策执行**：LLM 只负责意图理解和辅助推理，不直接执行系统命令
- **安全纵深防御**：7层安全防护体系，从输入护栏到审计链
- **职责分离**：控制节点（推理和编排）与目标机（命令执行）物理分离
- **RBAC 权限控制**：三级权限分级（READ → OP → ADMIN）

### 1.3 技术栈

| 层级 | 技术选型 |
|------|----------|
| 后端框架 | FastAPI + Uvicorn |
| LLM 提供商 | DeepSeek API（可切换 OpenAI-compatible） |
| 实时通信 | WebSocket（聊天） + SSE（监控流） |
| 缓存/状态存储 | Redis（fakeredis fallback） |
| 审计持久化 | SQLite + aiosqlite |
| MCP 协议 | JSON-RPC 2.0 over HTTP |
| 前端 | Vue 3 + Vite + Pinia |
| 部署 | systemd + venv + Nginx（原生） |
| 目标平台 | 麒麟 V11 + LoongArch |

## 2. 整体架构

### 2.1 三层架构

```
┌─ 用户浏览器 ──────────────────────────────────────────┐
│  前端: Vue 3 + Vite (端口 5173 dev / Nginx :443 prod) │
└──────────────────────┬────────────────────────────────┘
                       │ HTTPS / WSS
┌─ 控制节点 ───────────────────────────────────────────┐
│  Nginx :443 → 静态文件 + API 反向代理 + WSS 升级      │
│  Backend :8000 → FastAPI + 多 Agent 编排 + LLM 路由   │
│  Redis :6379 → 会话缓存 + 确认状态存储 + 任务持久化   │
│  SQLite → 审计日志 (哈希链防篡改)                     │
└──────────────────────┬────────────────────────────────┘
                       │ HTTPS + Bearer Token
┌─ 麒麟 V11 目标机 (LoongArch) ────────────────────────┐
│  MCP Server :8001 → 系统信息 / 服务管理 / 日志读取 / …│
│  权限: agent-read (只读) / agent-op (sudo 白名单)     │
└──────────────────────────────────────────────────────┘
```

## 4. 后端功能模块

### 4.1 API 接口层

#### 4.1.1 接口清单

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| `GET` | `/health` | 否 | 健康检查，返回 `{"status":"ok","version":"0.1.0"}` |
| `WS` | `/ws/chat/{session_id}` | Token | WebSocket聊天，串联安全检测→LLM→审计完整流程 |
| `GET` | `/api/sessions` | Token | 列出所有会话 |
| `POST` | `/api/sessions` | Token | 创建新会话 |
| `GET` | `/api/sessions/{session_id}` | Token | 获取单个会话详情 |
| `DELETE` | `/api/sessions/{session_id}` | Token | 删除会话 |
| `GET` | `/api/monitor/stream` | Token | SSE系统监控流 |
| `GET` | `/api/audit` | Token | 审计日志查询（分页: `?limit=&offset=`） |
| `GET` | `/api/config/whitelist` | Token | 查看三级白名单 |
| `PUT` | `/api/config/whitelist` | ADMIN Token | 更新白名单 |
| `POST` | `/api/actions/precheck` | Token | 修复动作预检查 |
| `POST` | `/api/actions/execute` | Token | 执行修复动作 |
| `GET` | `/api/actions` | Token | 查询修复动作状态 |
| `GET` | `/api/actions/{action_id}` | Token | 查询单个修复动作状态 |

#### 4.1.2 WebSocket 聊天流程 (`api/chat.py`)

1. 客户端通过 `ws://host/ws/chat/{session_id}?token=xxx` 连接
2. 连接建立后进行Token认证校验
3. 用户发送消息 → 进入编排器处理
4. 编排器依次调用safety_guard → intent_agent → diagnose_agent → [工具调用] → reporter_agent → fix_planner_agent
5. 处理结果通过WebSocket推送回客户端（支持流式输出和阶段通知）
6. 对话结束自动写入审计日志

#### 4.1.3 SSE 监控流 (`api/monitor.py`)

实时推送系统指标数据，供前端SysMonitor组件消费。推送内容包含CPU、内存、磁盘、网络等指标。

#### 4.1.4 修复动作 API (`api/actions.py`)

提供修复动作的完整生命周期管理：
- `precheck`: 执行前安全检查
- `execute`: 执行修复动作
- 查询接口: 查询动作状态和结果

#### 4.1.5 会话 API (`api/sessions.py`)

会话的完整CRUD操作，支持列表查询、创建、详情查看、删除。

#### 4.1.6 审计 API (`api/audit.py`)

分页查询审计日志，支持offset/limit参数。

#### 4.1.7 配置 API (`api/config.py`)

白名单的查看（所有认证用户）和修改（仅ADMIN），支持三级白名单（READ/OP/ADMIN）。

### 4.2 多 Agent 编排流水线

#### 4.2.1 整体调用链

```
用户输入
  ↓
SafetyGuard.analyze_user_input()          # 安全护栏
  ↓（reject/confirm/allow）
IntentAgent.detect()                      # 意图识别
  ↓
Orchestrator.run()                        # 编排主循环
  ├─ DiagnoseAgent.plan()                 # 诊断规划
  ├─ AgentHarness.run_tool()              # 工具执行（MCP调用）
  ├─ ReporterAgent.generate()             # 报告生成
  └─ FixPlannerAgent.plan()               # 修复规划 → FixOption列表
       ↓
ActionService.precheck() → execute()      # 修复动作执行
  ↓
审计日志写入
```

#### 4.2.2 Orchestrator（编排器）— `services/orchestrator.py`

**职责**: 协调多个 Agent 的执行流程，管理整个对话生命周期。

**关键功能**:
- 接收WebSocket消息，启动Agent流水线
- 按阶段推进：安全检测 → 意图识别 → 诊断 → 报告 → 修复规划
- 支持规则版和LLM增强版双路径，LLM不可用时自动fallback
- 通过WebSocket向客户端发送阶段性进度通知
- 支持接收用户确认和交互

#### 4.2.3 IntentAgent（意图识别）— `services/intent_agent.py`

**职责**: 识别用户输入的自然语言意图。

**支持的9种意图**:
- `cpu_query` — CPU查询
- `memory_query` — 内存查询
- `disk_query` — 磁盘查询
- `load_query` — 负载查询
- `network_query` — 网络查询
- `service_status_query` — 服务状态查询
- `log_query` — 日志查询
- `root_cause_analysis` — 根因分析
- `command_execute` — 命令执行
- `unknown` — 意图不明确（兜底）

**实现方式**:
- 规则版: `detect(content)` — 基于关键词和正则匹配，速度快，不依赖LLM
- LLM增强版: `detect_with_llm(content)` — 通过LLM进行语义理解，失败时自动fallback到规则版
- 辅助提取: `_extract_service(text)` 提取服务名，`_extract_port(text)` 提取端口号

#### 4.2.4 DiagnoseAgent（诊断Agent）— `services/diagnose_agent.py`

**职责**: 根据意图和上下文，制定诊断计划并执行。

**功能**:
- `plan()` / `plan_with_llm()`: 根据意图生成诊断步骤
- 确定需要调用的MCP工具及参数
- 收集诊断结果，整理为结构化数据供ReporterAgent使用

#### 4.2.5 ReporterAgent（报告生成Agent）— `services/reporter_agent.py`

**职责**: 将诊断结果汇总为可读的自然语言报告。

**功能**:
- `generate()` / `generate_with_llm()`: 基于诊断数据生成报告
- 报告包含问题描述、诊断发现、根因分析和建议
- 支持规则版模板和LLM生成两种模式

#### 4.2.6 FixPlannerAgent（修复规划Agent）— `services/fix_planner_agent.py`

**职责**: 根据诊断结果生成修复方案。

**功能**:
- `plan()` / `plan_with_llm()`: 生成修复步骤列表
- 输出结构化的 `FixOption` 列表，每个选项包含：
  - 操作描述
  - 所需命令
  - 风险等级
  - 是否需要确认

#### 4.2.7 AgentHarness（Agent框架）— `services/agent_harness.py`

**职责**: 提供Agent执行的通用框架，封装工具调用和状态管理。

**功能**:
- `run_tool()`: 执行MCP工具调用
- 管理工具调用的生命周期
- 处理Mock模式和Real模式的切换
- 提供Agent执行的上下文传递

#### 4.2.8 AgentContext（Agent上下文）— `services/agent_context.py`

**职责**: 管理Agent执行过程中的上下文数据。

**功能**:
- 存储会话级别的上下文信息
- 在多个Agent之间传递共享数据
- 管理对话历史

#### 4.2.9 ActionService（动作服务）— `services/action_service.py`

**职责**: 修复动作的执行管理。

**功能**:
- `precheck()`: 执行前安全检查，验证命令合法性
- `execute()`: 执行修复动作，支持异步执行
- 状态管理: pending → running → success/failed
- 结果持久化

### 4.3 安全护栏系统

#### 4.3.1 SafetyGuard（安全护栏）— `services/safety_guard.py`

**职责**: 对用户输入进行多层安全检查。

**输入处理函数** `analyze_user_input(content)`:
1. **长度检查**: 超过 `MAX_INPUT_LENGTH` 的输入被拒绝
2. **高危正则黑名单**: 匹配 `rm -rf /`、`mkfs`、`dd`、fork bomb 等模式 → `reject`
3. **Prompt 注入检测**（委托给 `prompt_guard.py`）
4. **中危关键词**: `kill -9`、`chmod 777` 等 → `confirm`

**工具调用裁决函数**:
1. 工具分发检查，确保工具在允许列表中
2. 高危模式拦截：检测 `;`、`&&`、`|`、`` ` ``、`$()` 等Shell元字符
3. 角色分级裁决：viewer → operator → admin（medium需确认，high恒拒绝）

**返回值**: `reject`（拒绝）/ `confirm`（需确认）/ `allow`（允许）

#### 4.3.2 PromptGuard（Prompt注入检测）— `core/prompt_guard.py`

**职责**: 五层Prompt注入检测。

**五层检测**:
1. **控制字符检测**: 检查Null字节等不可见控制字符
2. **Unicode混淆检测**: 检测同形异义字符攻击
3. **重复字符检测**: 检测异常长的重复序列
4. **关键词检测**: 检测已知注入模式（ignore previous instructions, system prompt等）
5. **语义边界检测**: 检测角色扮演和指令覆盖模式

#### 4.3.3 SecurityRules（安全规则）— `core/security_rules.py`

**职责**: 安全规则数据的唯一来源。

**功能**:
- 定义三级RBAC白名单规则
- 提供危险模式正则定义
- 提供默认的安全配置
- 作为安全规则的单一数据源

#### 4.3.4 Security（风险分级）— `core/security.py`

**职责**: 风险分级和裁决逻辑。

**功能**:
- 定义风险等级枚举: `reject`, `confirm`, `allow`
- RBAC权限检查
- 权限与操作映射

## 8. 安全模型

### 8.1 七层纵深防御

```
用户输入
  ↓
第1层: 安全护栏 (safety_guard.py)
  ├─ 长度检查 (MAX_INPUT_LENGTH)
  ├─ 高危正则黑名单 (rm -rf /, mkfs, dd, fork bomb等)
  ├─ Prompt注入检测 (五层: 控制字符→Unicode混淆→重复字符→关键词→语义边界)
  └─ 中危关键词 (kill -9, chmod 777等)
       ↓ 返回: reject / confirm / allow
  ↓
第2层: 意图识别 (intent_agent.py)
  ↓
第3层: 多Agent编排 (orchestrator.py)
  ├─ DiagnoseAgent → 根因分析
  ├─ FixPlannerAgent → 修复方案生成
  └─ ReporterAgent → 报告生成
       ↓ 修复动作
  ↓
第4层: 工具调用安全裁决 (safety_guard.py + security_rules.py)
  ├─ 工具分发检查 + 高危模式拦截
  ├─ 危险模式拦截 (;, &&, |, `, $() 等)
  └─ 角色分级: viewer→operator→admin (medium需确认，high恒拒绝)
       ↓
第5层: MCP Server执行 (麒麟目标机)
  ├─ agent-read: 只读 (sys_info, log_reader, net_monitor)
  └─ agent-op: sudo白名单 (systemctl status/start/stop/restart/reload)
       ↓
第6层: cgroup资源隔离 (mcp-server/sandbox.py)
  ├─ CPU配额限制 (默认50%)
  ├─ 内存上限 (默认256MB)
  ├─ PID数量限制 (防fork bomb)
  └─ 可通过.env配置: CGROUP_ENABLED=true
       ↓
第7层: 审计记录 (哈希链防篡改)
  ├─ SQLite audit_chain表
  └─ SHA256链式哈希: hash(prev_hash + current_data)
```

### 8.2 RBAC 权限模型

| 角色 | 权限 | Token前缀 |
|------|------|-----------|
| READ (只读) | 查看系统信息、日志、监控、审计 | `read:` |
| OP (操作) | READ权限 + 服务管理、命令执行 | `op:` |
| ADMIN (管理员) | OP权限 + 白名单配置、系统配置 | `admin:` |

### 8.3 认证方式

- HTTP API: `Authorization: Bearer <token>` 头
- WebSocket: 连接URL参数 `?token=xxx`
- 支持单Token和多Token分级两种模式

```
  ├─ {"type":"message","content":"系统负载过高"} ───────────>│                                                │
  │                                                        ├─ SafetyGuard.analyze() → allow                 │
  │                                                        ├─ IntentAgent.detect() → load_query             │
  │<── {"type":"status","stage":"intent","intent":"load_query"} ─┤                                           │
  │                                                        ├─ DiagnoseAgent.plan()                           │
  │                                                        ├─ {"tool":"sys_info","params":{}} ──────────────>│
  │                                                        │                                                ├─ 执行系统信息采集
  │                                                        │<── {"cpu_load":...,"memory":...} ───────────────┤
  │<── {"type":"status","stage":"diagnosing"} ──────────────┤                                                │
  │                                                        ├─ ReporterAgent.generate()                       │
  │<── {"type":"report","content":"系统负载偏高，CPU使用率92%..."} ─┤                                        │
  │                                                        ├─ FixPlannerAgent.plan()                         │
  │<── {"type":"fix_options","options":[{...},...]} ────────┤                                                │
  │                                                        │                                                │
  │<── 用户确认修复方案 ──────────────────────────────────────>│                                                │
  │                                                        ├─ ActionService.precheck() → execute()            │
  │                                                        ├─ 审计日志写入                                   │
  │<── {"type":"done"} ──────────────────────────────────────┤                                                │
```
